# Oly Music

منصّة عربية لنشر الموسيقى والاستماع إليها، بواجهة RTL وخط **Cairo** محلي وتصميم خمري داكن. المشروع يتضمن واجهة React، وخادم Node.js فعليًا، ومخطط PostgreSQL جاهزًا لـ Supabase. لا يعتمد تسجيل الدخول أو صلاحيات الإدارة على بيانات يرسلها المتصفح.

## التشغيل السريع

يتطلب **Node.js 22.13+** وnpm.

```sh
npm ci
npm run dev
```

يفتح التطبيق على المنفذ `5173`، ويقبل الوصول عبر `0.0.0.0`. يمكن تغيير المنفذ بمتغير `PORT`. يبني أمر التشغيل الواجهة ويقدمها مع الـAPI من المصدر نفسه، دون اتصالات متصفح إلى localhost أو اعتماد على CDN.

**وضع المعاينة:** عند غياب `DATABASE_URL` يعمل الموقع بقاعدة SQLite دائمة في `data/oly.sqlite`، مع خمسة مقاطع موسيقية تجريبية وأغلفة أصلية وثلاثة بنرات. هذا الوضع محلي وليس مشروع Supabase مُنشأً بالنيابة عنك. التسجيل والرفع والبلاغات والمراجعة حقيقية داخل هذه القاعدة، ولا تُفقد عند تحديث الصفحة.

**تجربة الإدارة:** من «حسابك على Oly» ← «تسجيل الدخول» ← **«معاينة لوحة الإدارة»**. هذه الإمكانية حصرية للمعاينة المحلية. الحساب المخصص لها `admin@oly.local` وكلمة سره `OlyDemo!2026`. لا تُستخدم بيانات المعاينة لإنشاء أدمن على PostgreSQL أو في الإنتاج. يمكن تعطيل المعاينة محليًا بضبط `DEMO_MODE=false` عند التهيئة الأولى.

## الربط الفعلي مع Supabase

1. أنشئ مشروع Supabase جديدًا أو قاعدة مخصصة لهذا التطبيق. الجداول العامة في المخطط مخصصة لـ Oly، لذلك لا تطبّق المخطط على جداول تحمل الأسماء نفسها داخل مشروع آخر دون مراجعة.
2. انسخ `.env.example` إلى `.env` على **الخادم فقط**، أو استخدم مدير الأسرار في الاستضافة.
3. من **Connect** في Supabase، انسخ رابط PostgreSQL (يفضّل **Session Pooler** لخادم Node دائم) إلى `DATABASE_URL`. استبدل كلمة سر قاعدة البيانات بالقيمة الصحيحة مع ترميز الأحرف الخاصة في الرابط. لا تضع المفاتيح في محادثة أو في متغيرات `VITE_` العامة.
4. اضبط `ADMIN_EMAIL` و`ADMIN_PASSWORD` قبل أول تشغيل لإنشاء حساب الإدارة الأول. استخدم كلمة سر طويلة وفريدة. أدمن الإنتاج يسجّل الدخول بالنموذج العادي.
5. المخطط موجود في **`supabase/schema.sql`**. يهيّئه الخادم عند بدء التشغيل بهوية قاعدة البيانات الموثوقة. يمكن معاينته وتشغيله من SQL Editor أيضًا. يتطلب الاتصال صلاحية إنشاء الجداول وضبط RLS. يتم التحقق من شهادة TLS؛ إذا طلب اتصالك شهادة جذر، استخدم `PG_CA_CERT` مع شهادة Supabase الصحيحة. لا تعطل التحقق من الشهادات في الإنتاج.
6. للملفات الصوتية والصور على **Supabase Storage**: نفّذ `supabase/storage.sql` لإنشاء الحاوية **الخاصة** `oly-media`، ثم اضبط `SUPABASE_URL` و`SUPABASE_SERVICE_ROLE_KEY` و`SUPABASE_STORAGE_BUCKET`. يبقى مفتاح الخدمة على الخادم. لا تنشئ سياسة قراءة عامة للحاوية.
7. إذا لم تهيئ Storage، تُحفظ الملفات في `data/media`؛ اربط هذا المسار بقرص دائم (يمكن تغييره بـ`MEDIA_PATH`). التخزين المحلي غير مناسب للأقراص المؤقتة في منصات الاستضافة.
8. افتراضيًا يكون كتالوج PostgreSQL فارغًا. لإضافة الأغاني النموذجية اضبط `SEED_CATALOG=true` عند التهيئة الأولى. لا يؤدي هذا الخيار إلى إنشاء حساب إدارة تجريبي.

```sh
npm ci
npm run build
NODE_ENV=production npm start
```

**يتطلب وضع الإنتاج `DATABASE_URL` صراحةً ولا يرجع إلى SQLite بصمت.** استضف خادم Node مع HTTPS؛ رفع `dist` وحده إلى استضافة ملفات ثابتة لا يشغّل حسابات المستخدمين أو لوحة الإدارة. تُستثنى ملفات `.env` وقاعدة البيانات والملفات الخاصة من مجلد الواجهة المقدم للمتصفح.

### بنية البيانات والحسابات

- `public.users`: `id`, `username` فريد دون حساسية لحالة الأحرف، `email` فريد، `password`، وصورة الحساب والنبذة والصلاحية والتوثيق والحظر وتوقيت تغيير اسم المستخدم.
- **`password` يحتوي على تجزئة scrypt مملّحة فقط**. لا تُخزن كلمة السر كنص صريح ولا يُعاد الحقل ضمن استجابات الـAPI. يستخدم المشروع نظام جلسات خادميًا مستقلًا، وليس حسابات `auth.users` في Supabase Auth.
- `public.songs`: العنوان والفنان والتصنيف والملف الصوتي والغلاف و`user_id` والحالة `pending / approved / rejected` وعدّاد البلاغات والتشغيل والمدة. الحقل `flagged` يميز المحتوى المُخفى بسبب البلاغات دون اختراع حالة نشر رابعة.
- جداول مستقلة للجلسات، الإعجابات، المفضلة، المتابعات، البلاغات، الإشعارات، البنرات، الملفات، الزوار وأحداث التشغيل.
- تفعيل RLS وإلغاء أذونات `anon` و`authenticated` على جداول التطبيق يمنع الوصول المباشر إلى البيانات من PostgREST؛ طلبات الواجهة تمر عبر الخادم الذي يتحقق من هوية الجلسة والصلاحية.
- الجلسة في Cookie من نوع HttpOnly، مع Secure وPartitioned عند HTTPS لدعم المعاينة المضمّنة، ولا تُخزّن الجلسات أو كلمات السر في localStorage. تُحفظ تفضيلات المشغّل غير الحساسة فقط في المتصفح.

## ما الذي يعمل؟

### الاستماع والمكتبة
- مشغّل بمسار زمني، تقديم وتأخير، التالي والسابق، صوت وكتم، تكرار، ترتيب عشوائي وقائمة تشغيل. يبدأ الصوت بتفاعل المستخدم ولا يوجد تشغيل تلقائي عند فتح الموقع.
- البحث بعنوان الأغنية أو الفنان أو التصنيف، وتصنيفات مهرجانات وحزينة وراب وشعبي. التصفية بالأحدث أو التشغيل أو الإعجابات أو الحسابات الموثّقة.
- عدّاد تشغيل خادمي يحدّ من التكرار للأغنية نفسها من جلسة الزائر نفسها خلال 30 دقيقة.
- إعجاب ومفضلة مستقلان؛ يُفتح خيار «حفظ في المفضلة» من تفاصيل الأغنية. متابعة الفنانين، ملف لكل فنان، ونسخ رابط مباشر لأغنية منشورة.
- ثلاثة بنرات مستطيلة تتعاقب كل 16 ثانية، مع تحكم يدوي وإيقاف التبديل عند التفاعل. يُحترم تفضيل تقليل الحركة.

### الحسابات والنشر
- تسجيل حساب باسم مستخدم وبريد فريدين وكلمة سر، ودخول وخروج وجلسة مستمرة.
- تغيير الصورة والنبذة، وتغيير اسم المستخدم مرة كل 30 يومًا. تبدأ المهلة من التسجيل ويُفرض القيد في قاعدة البيانات عبر مسار الخادم، وليس بمجرد تعطيل زر.
- «إضافة أغنية» يقبل MP3/M4A/WAV/OGG حتى 40 MB وصورة JPG/PNG/WebP حتى 5 MB. يتم التحقق من ترويسة الملف وحجمه. الغلاف اختياري ويوجد غلاف بديل.
- كل رفع جديد يكون **معلقًا**. تُتاح معاينة الملف غير المنشور لصاحبه والأدمن فقط. بعد الموافقة يظهر الإصدار باسم الحساب وصورته وعلامة التوثيق إن وُجدت.

### المراجعة والخصوصية
- الإبلاغ من تفاصيل كل أغنية، بسبب محدد وملاحظة اختيارية. يقبل الخادم بلاغًا واحدًا لكل حساب لكل أغنية أثناء دورة المراجعة، ولا يسمح بالإبلاغ عن الأغنية الخاصة بالحساب.
- **عند البلاغ الخامس من خمسة حسابات مختلفة** تُخفى الأغنية تلقائيًا، وتصبح `pending` مع `flagged=1`، وتظهر في قائمة الإبلاغات بدل قائمة الرفع الجديدة. لا يُتاح رابط صوت جديد للمستمعين أثناء الإخفاء. روابط Storage الموقّعة الصادرة سابقًا تنتهي خلال دقيقتين.
- يستمع الأدمن للأغنية ويراجع تفاصيل البلاغات، ثم يرفضها أو يعيد نشرها. تُصفّر البلاغات النشطة عند إنهاء المراجعة. يظهر سبب الرفض لصاحب الأغنية عند إضافته.
- لوحة الإدارة بها تبويبات الحسابات والمعلقة والمقبولة والمرفوضة والإبلاغات والمحظورين والبنرات. تدعم التوثيق وإلغاءه، والحظر وفكه، وتغيير صورة كل بنر وعنوانه ووصفه والأغنية المرتبطة به.
- الحظر يمنع دخول الحساب وطلباته الحالية ويخفي أغانيه العامة. لا يمكن حظر الأدمن عبر هذه الآلية.
- **عدد الحسابات والزوار الفريدين** (وفق Cookie الزائر، لا ادّعاء بأنه عدّ للأشخاص) يُعاد فقط من مسار الإدارة المحمي. لا تعرض الواجهة العامة هذه الإحصاءات.
- إشعار عام عند نشر أغنية، وإشعارات خاصة بالإدارة عند التسجيل أو البلاغ أو الرفع، وإشعارات شخصية لقرار المراجعة والتوثيق. تتحدث الإشعارات دوريًا كل 7 ثوانٍ عند فتح التطبيق. صوت جرس واضح قابل للكتم؛ يبدأ بعد أول تفاعل وفق سياسة تشغيل الصوت بالمتصفح. الإشعارات داخل الموقع وليست Push بعد إغلاقه.
- صفحة المطوّر تحتوي مواضع Instagram وFacebook وGitHub **بلا روابط فعلية** كما طُلب.

## الاختبارات

```sh
npm test                    # دورة HTTP كاملة في قاعدة منفصلة مؤقتة
npx playwright install --with-deps chromium
npm run build
npm run test:ui             # اختبارات تفاعل ومتصفح وهاتف على نسخة معزولة
```

تتحقق الاختبارات من التفرد والصلاحيات ورفع الملفات الخاصة والموافقة والتشغيل والتفاعل وخمسة بلاغات مستقلة والحظر وفكه والإشعارات والبنرات. لا تكتب الاختبارات في قاعدة المعاينة الحية. اختبارات PostgreSQL الاختيارية: استخدم `TEST_DATABASE_URL` لقاعدة **اختبار مخصصة وفارغة** تحوي دورَي Supabase `anon` و`authenticated`. لا تستخدم رابط الإنتاج للاختبارات.

## الملفات الرئيسية

```text
src/                   واجهة React العربية والمشغّل والحوارات ولوحة التحكم
server/index.mjs       خادم HTTP، التسجيل، المراجعة، الملفات والصلاحيات
server/db.mjs          محوّل PostgreSQL / SQLite والمعاملات والتهيئة
supabase/schema.sql    جداول PostgreSQL والفهارس وحماية الوصول
supabase/storage.sql   حاوية الملفات الخاصة الاختيارية
public/art/            الأغلفة والبنرات المحلية
public/audio/          مقاطع موسيقية آلية تجريبية أصلية
scripts/make-audio.mjs مولّد المقاطع عند الحاجة (يتطلب ffmpeg)
```

الأسماء الفنية والإصدارات التجريبية أمثلة توضيحية، وليست تسجيلات منسوبة إلى فنانين حقيقيين. الأغلفة والبنر الرئيسي مولّدة للتجربة. صور الحسابات التوضيحية الأخرى من Unsplash. خط Cairo مضمن محليًا، وترخيصه في `public/fonts/OFL.txt`.

**التحقق المنفّذ:** نجحت دورة الـAPI على SQLite وعلى خادم PostgreSQL 15 مؤقت ومعزول، بما فيها الحجب عند البلاغ الخامس واستعادة النشر. تم التحقق من RLS على الجداول الاثني عشر ومن عدم امتلاك `anon` صلاحية قراءة الحسابات. نجحت كذلك اختبارات المتصفح للتسجيل والرفع والمراجعة وتعديل البنرات والتشغيل والتصفح على الهاتف. هذه الاختبارات لا تعني إنشاء مشروع Supabase سحابي أو ربطه دون بيانات اتصالك.
